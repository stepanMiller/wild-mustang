# Architecture

Этот документ фиксирует предлагаемую архитектуру Wild Mustang. На текущем этапе архитектура не реализована в коде.

## Цели

- Поддерживать долгосрочную разработку небольшими безопасными итерациями.
- Разделять инфраструктуру, игровой поток, доменную логику и представление.
- Не привязывать бизнес-логику к конкретным сценам Unity без необходимости.
- Сохранять возможность постепенного введения тестов и assembly definitions.

## Предлагаемые слои

1. **Bootstrap**
   - Точка входа приложения.
   - Инициализация сервисов.
   - Загрузка конфигураций.
   - Переход к `MainMenu` или `Game`.

2. **Game Flow**
   - Управление состояниями приложения.
   - Навигация между сценами.
   - Жизненный цикл игровой сессии.

3. **Feature Modules**
   - Будущие модули геймплея, UI, аудио, сохранений и мира.
   - Каждый модуль должен иметь чёткие границы ответственности.

4. **Domain / Data**
   - Чистые модели данных.
   - ScriptableObject-конфиги.
   - Правила, не зависящие от визуального представления.

5. **Presentation**
   - MonoBehaviour-компоненты.
   - UI views.
   - Привязка анимаций, звука и визуальных эффектов.

6. **Infrastructure**
   - Сохранения.
   - Загрузка ресурсов.
   - Платформенные сервисы.
   - Интеграции внешних SDK через интерфейсы.

## Принципы

- Сцены не должны становиться контейнерами всей логики.
- Зависимости должны идти от внешних слоёв к внутренним контрактам, а не наоборот.
- Новые системы добавляются только при появлении конкретной задачи.
- Сложность вводится постепенно: сначала простая реализация, затем выделение модулей при реальной необходимости.
